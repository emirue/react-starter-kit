## Workspace commands

Run from the repository root:

| Command | Description |
| --- | --- |
| `{{pmRun}} dev` | Start every app in development mode |
| `{{pmRun}} build` | Build all packages and apps in dependency order |
| `{{pmRun}} typecheck` | Type-check every package |
| `{{pmRun}} lint` | Lint every package |
| `{{pmRun}} test` | Run unit tests once |

Run a task for one app only:

```bash
{{pmFilterDev}}
{{pmFilterBuild}}
```

## Layout

```text
apps/
  {{appName}}/      React + Vite application ({{appDir}})
<!-- @if pkg-shared || pkg-types || pkg-ui -->
packages/
<!-- @endif -->
<!-- @if pkg-shared -->
  shared/   browser-safe runtime helpers (@{{projectName}}/shared)
<!-- @endif -->
<!-- @if pkg-types -->
  types/    types shared with TypeScript backends (@{{projectName}}/types)
<!-- @endif -->
<!-- @if pkg-ui -->
  ui/       shared React components (@{{projectName}}/ui)
<!-- @endif -->
```

Shared packages are real workspace packages: they build to `dist/` with type
declarations and are linked with `workspace:*`, so imports resolve the same way
in TypeScript, Vite and Node.js.

## Adding a backend

Put a backend in its own directory, for example `apps/api`. A TypeScript backend
(NestJS, Express) can join the workspace and depend on shared packages. A
non-Node backend (ASP.NET Core, Go, ...) should live outside the `packages`
globs; connect it through HTTP. See the app README for the API proxy.
