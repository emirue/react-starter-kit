# Frontend architecture of generated apps

This is the standard every app generated by create-produx-app follows. It is based on Feature-Sliced Design (FSD) v2.1 ("pages first"), uses only the layers the app needs, and is enforced by ESLint (`eslint-plugin-boundaries`) inside the normal `lint` script.

The analysis that led here is in [../refactoring/audit-report.md](../refactoring/audit-report.md); the file map and plan are in [../refactoring/migration.md](../refactoring/migration.md), the evidence in [../refactoring/validation-report.md](../refactoring/validation-report.md).

This one document holds the layer rules, dependency rules and the component, state, API, design-system and testing standards. They were planned as separate files (`layer-rules.md`, `dependency-rules.md`, `docs/standards/*.md`) and merged here because each would have been a few lines repeating the others; the same rules reach generated projects through their `AGENTS.md` / `CLAUDE.md` (`templates/shared/ai-rules.md`).

## Layers

| Layer      | Has slices          | Holds                                                                                                                                                                                                                             | Must not hold             |
| ---------- | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------- |
| `app`      | no (segments/files) | `app.tsx` (composition), `providers.tsx`, `router.tsx` (React Router), `route-error.tsx`, `error-boundary.tsx`, `layouts/*` (layouts for the whole app or a routing subtree), `model/*` (app-shell state, e.g. the admin sidebar) | business logic, domain UI |
| `pages`    | yes                 | one slice per route-level screen: `ui/`, `api/` (page-only requests and query options), `model/` (schemas, search-param parsing, page state), `index.ts`                                                                          | imports of other pages    |
| `features` | yes                 | user actions reused by two or more places: `ui/`, `model/`, `api/`, `index.ts`                                                                                                                                                    | imports of other features |
| `entities` | yes                 | not generated by default; created when a second page needs the same domain data (see "Promoting code")                                                                                                                            | user actions              |
| `shared`   | no (segments)       | domain-free code: `ui/` (design system), `api/` (HTTP client, `ApiError`, QueryClient factory, Orval output), `lib/` (one focused library per folder), `config/`                                                                  | business logic            |

Outside the layers (not checked as layers):

- `src/main.tsx` (Vite entry), `src/index.css` (global styles and design tokens), `src/vite-env.d.ts`
- `src/routes/**` and `src/routeTree.gen.ts` (TanStack Router only). Route files are classified as `app` and stay thin: they bind a page component and search validation exported by the page slice.
- `src/mocks/**` (MSW) and `src/test/**` (test setup and helpers)

The `widgets` layer is not used: FSD v2.1 makes layers optional and keeps UI that one page uses inside that page.

## Dependency rules

| from \ to                        | app |     pages      |    features    |       entities       | shared |
| -------------------------------- | :-: | :------------: | :------------: | :------------------: | :----: |
| app, `src/routes/**`, `main.tsx` |  ✓  |   index only   |   index only   |      index only      |   ✓    |
| pages                            |  —  | own slice only |   index only   |      index only      |   ✓    |
| features                         |  —  |       —        | own slice only |      index only      |   ✓    |
| entities                         |  —  |       —        |       —        | own slice; `@x` only |   ✓    |
| shared                           |  —  |       —        |       —        |          —           |   ✓    |

- A slice's public API is its `index.ts` with explicit named exports. `export *` is not used.
- `shared/ui` and `shared/lib` are imported per module: `@/shared/ui/button`, `@/shared/lib/theme`. There is no `shared/ui/index.ts`.
- Inside a slice use relative imports; between slices use `@/`. A slice never imports itself through `@/`.
- Lazy route imports target page indexes: `import("@/pages/users")`.

## Target tree

React Router, Admin preset with examples (other presets generate a subset; empty folders are never created):

    layouts/  root-layout.tsx | admin-layout.tsx  examples-layout.tsx

  pages/
    home/            index.ts  ui/home-page.tsx              (not admin)

    not-found/       index.ts  ui/not-found-page.tsx

    examples/        index.ts  ui/examples-page.tsx                                            (examples)
    todos-example/   index.ts  ui/{todos-page,todo-list}.tsx  api/  model/                     (examples + tanstack-query)
    sign-up-example/ index.ts  ui/{sign-up-page,sign-up-form}.tsx  api/  model/                (examples + forms)
    counter-example/ index.ts  ui/{counter-page,counter}.tsx  model/                           (examples + zustand)
  features/
    switch-theme/    index.ts  ui/mode-toggle.tsx            (theme)
  shared/
    ui/      button.tsx card.tsx input.tsx … (shadcn/ui) page-header.tsx state.tsx error-fallback.tsx page-loader.tsx
    api/     http-client.ts api-error.ts query-client.ts orval-mutator.ts generated/
    lib/     theme/  use-mobile.ts  utils.ts
    config/  env.ts

TanStack Router: `src/routes/` mirrors the routes; `app/router.tsx` creates the router; there is no React Router `router.tsx`.

Examples need a router. With `--router none` no example pages are generated.

## Component patterns

- A page component (`ui/<name>-page.tsx`) composes; data views and forms are separate components in the same `ui/` segment (`todo-list.tsx`, `users-table.tsx`, `sign-up-form.tsx`).
- Components receive data and callbacks through props when the state lives in the URL or a parent (`TodoList({ filter, onFilterChange })`); they own a query or mutation when they are the only consumer.
- Every input has a visible `Label` with `htmlFor`; field errors are linked with `aria-describedby` and announced (`role="alert"` for form-level errors).
- No business logic in `shared/ui`: shared components are generic and styled with variants (`cva`).

## State management

| State                                               | Where                                                                                       | Example                                                                 |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Server data                                         | TanStack Query; key factory and `queryOptions` in the slice's `api/`                        | `pages/todos-example/api/todo-queries.ts`                               |
| URL state (filters, tabs, pagination worth sharing) | Search params; parsed in the slice's `model/`                                               | `?filter=` via `parseTodoFilter` / `validateTodosSearch`                |
| Form state                                          | React Hook Form + Zod schema in `model/`                                                    | `pages/sign-up-example/model/sign-up-schema.ts`                         |
| Client state shared across components               | Zustand store with selectors in the owning slice's `model/`; app-shell state in `app/model` | `pages/counter-example/model/counter-store.ts`, `app/model/ui-store.ts` |
| Local UI state                                      | `useState` in the component                                                                 | dialog open, input text                                                 |

- Server data is never copied into Zustand or React state.
- Persist only preferences (`persist` with `partialize`), with keys prefixed by the app name (`<app>:ui`, `<app>:theme`).
- Context only for app-wide providers (theme).

## API patterns

- All requests go through `shared/api/http-client.ts` (or Orval's generated functions, which use `shared/api/orval-mutator.ts`); both reject with `ApiError` (`kind`, `status`, `details`), and `getErrorMessage()` produces the text shown by `ErrorState`.
- A slice's `api/` segment holds its request functions (`<domain>-api.ts`) and query options/mutations (`<domain>-queries.ts`). Pass TanStack Query's `signal` to every request.
- Mutations invalidate the affected keys through the key factory (`todoKeys.lists()`), and the UI locks only the item being saved.
- With Orval, the OpenAPI document is the single source of types: the slice's `model/` re-exports the generated types instead of redeclaring them.
- Defaults live in `shared/api/query-client.ts` (`staleTime` 30 s, `retry: 1`, no retries for mutations); per-query policies go in the slice's `queryOptions`.

## Design system

- **Tokens** live in `src/index.css` (`:root` and `.dark`): colors (oklch), radius scale, fonts. Components use semantic classes only (`bg-background`, `text-muted-foreground`, `border`, `bg-primary`, …). Raw palette classes (`bg-gray-500`, `text-red-600`, hex/rgb colors in className) are not used outside `src/index.css` and the vendored shadcn/ui files. With Tailwind and ESLint, `no-restricted-syntax` in `eslint.config.js` rejects them in every file outside `src/shared/ui`, so pages, features and the app stay on tokens after generation; a new color is a new token.
- **Typography**: page title `text-2xl font-semibold tracking-tight` (via `PageHeader`), section title `text-lg font-semibold`, body `text-sm`/`text-base`, secondary text `text-muted-foreground`.
- **Spacing**: Tailwind's 4 px scale; page padding `p-4 md:p-6`, stacks `gap-4`/`gap-6`, cards from `shared/ui/card`.
- **Components** come from `shared/ui` (shadcn/ui + `PageHeader`, `LoadingState`/`ErrorState`/`EmptyState`, `ErrorFallback`, `PageLoader`). Variants are expressed with `cva` in the component, not with ad-hoc class strings in pages.
- **States**: every data view shows loading (`LoadingState`, `role="status"`), error (`ErrorState`, `role="alert"`, retry) and empty (`EmptyState`) consistently.
- **Themes**: light, dark and system via `shared/lib/theme`; the toggle is the `switch-theme` feature.

## Responsive rules

- Mobile first; Tailwind breakpoints `sm` 640, `md` 768, `lg` 1024, `xl` 1280.
- No horizontal page overflow at 375 px. Wide content (tables) scrolls inside its own container.
- Navigation: the admin sidebar becomes a sheet below `md`; the root header wraps and keeps the theme toggle reachable (icons only below `sm`).
- Forms are single column; action rows wrap; grids collapse to one column on small screens.
- Touch targets are at least 32 px high (shadcn defaults).

## Accessibility rules (WCAG 2.2 AA)

- One `main` landmark per page, reached by a "Skip to content" link that is the first focusable element. Navigation is inside `nav` with an accessible name.
- Loading regions use `role="status"` with a name; errors use `role="alert"`.
- Text meets 4.5:1 contrast with the design tokens in both themes.
- A page error never removes the app shell: route error boundaries sit inside the layout.

## Storybook (feature `storybook`)

- Stories live next to components: `src/shared/ui/button.stories.tsx`, `src/features/switch-theme/ui/mode-toggle.stories.tsx`.
- `src/shared/ui/design-tokens.mdx` documents colors, typography, spacing and radius from `src/index.css`.
- Addons: docs, a11y (violations fail story tests), themes (light/dark via the `dark` class), vitest (stories run as browser tests with `test:storybook`).
- Scripts: `storybook` (dev), `build-storybook`, `test:storybook`. With Storybook, Vitest has two projects in `vite.config.ts`: `unit` (jsdom; `test`, `test:run`) and `storybook` (Chromium through `@vitest/browser-playwright`; `test:storybook`).
- `eslint-plugin-storybook` (`flat/recommended`) lints stories when ESLint is selected.

## Testing rules

- Unit/component tests sit next to the code (`*.test.ts(x)`), use `renderWithProviders` from `src/test/render.tsx` (shared QueryClient factory), and query by role/label.
- End-to-end tests (`e2e/*.spec.ts`, Playwright) cover: start page, navigation, 404, a page error keeping the shell, dark mode, and no horizontal overflow at 375 px.
- Story tests cover rendering and a11y of every story.

## Promoting code

Start in the page slice. When a second page needs the same thing:

1. A user action (UI + mutation) moves to `features/<action>` with an `index.ts`.
2. Domain types, schemas, read API and query options move to `entities/<domain>`.
3. Update the pages to import the new slice's index; `pnpm lint` reports anything that still reaches into the old location.

## Enforcement

`eslint.config.js` classifies every linted file under `src` into `app` (including `src/routes`), `pages`, `features`, `entities` or `shared`, and fails on:

- imports from a higher layer or a sibling slice,
- imports that bypass a slice's `index.ts`,
- files under `src` that belong to no layer (`boundaries/no-unknown-files`).

The entry files (`src/main.tsx`, `src/vite-env.d.ts`), `src/mocks/**`, `src/test/**` and generated files are ignored. Aliases are resolved through `eslint-import-resolver-typescript`. The CLI's validation runs `lint` after install, and the generated CI runs it on every push.
