# Dependency compatibility

Versions pinned into generated projects by this release (`src/config/dependency-versions.json`). "Latest stable" is the npm `latest` tag checked against the release history on 2026-11-24 (prereleases, release candidates and canaries excluded). "PASS" means the package was installed and exercised by the validation matrix ([validation-report.md](validation-report.md)) together with every other selected version; peer dependency warnings were checked with a full install of the manifest.

Sources: npm registry metadata (`npm view`), package changelogs and the research notes in [research/context7-references.md](research/context7-references.md).

## Compatibility notes

- **pnpm 11+ build approvals.** Install fails with `ERR_PNPM_IGNORED_BUILDS` when a dependency's install script is not approved. Only esbuild (brought in by orval) needs it; generated projects add `allowBuilds: { esbuild: true }` only when orval is selected.
- **pnpm minimum release age.** pnpm records packages published less than a day before install in `pnpm-workspace.yaml` (`minimumReleaseAgeExclude`). This affects projects generated within a day of a pinned version's release.
- **React Router 8** removed `react-router-dom`; `RouterProvider` comes from `react-router/dom`.
- **TanStack Table 9** replaced `useReactTable` with `useTable` and requires `features` (`tableFeatures`).
- **Vitest 5 + jest-dom 8**: jest-dom 8 peers `vitest >=5 <6`; with `globals: false` the setup file must call `cleanup`.
- **ESLint 10**: flat config only; use `reactHooks.configs.flat.recommended` and `reactRefresh.configs.vite()`. React Hooks 7 includes React Compiler rules; shadcn/ui's `use-mobile` hook violated `set-state-in-effect` and is replaced with a `useSyncExternalStore` version.
- **shadcn/ui (Radix)**: the sidebar's tooltips require `TooltipProvider`; the admin layout provides it.
- **MSW 3**: `onUnhandledRequest` became `onUnhandledFrame`; the package no longer has a postinstall, so the worker file is shipped with the template for the pinned version.
- **Orval 8** defaults to `fetch`; with `mock: true` it would need `@faker-js/faker`, so generated projects use hand-written MSW handlers instead. Generated apps use the function clients (`axios-functions` returns the data, `fetch` returns `{ data, status, headers }`) and wrap them in the page's own query options.
- **Storybook 10 + Vitest 5**: `@storybook/addon-vitest` peers `vitest`, `@vitest/browser` and `@vitest/browser-playwright` `^4 || ^5`, so `@vitest/browser` is pinned explicitly. Story tests run as a separate Vitest project (`storybook`) in Chromium; unit tests stay in jsdom (`unit`). `playwright` is pinned to the same version as `@playwright/test` so both use one browser build.
- **eslint-plugin-boundaries 7**: without an `import/resolver` setting, `@/` imports are classified as external and silently not checked; generated configs use `eslint-import-resolver-typescript`. Element descriptors' `mode` option is deprecated, so single entry files are ignored rather than modelled as file elements.
- **Docker**: `node:26-alpine` has no corepack, so the image installs the pinned pnpm with npm. `nginxinc/nginx-unprivileged` stable (1.30.6) trails the official image (1.30.8).
- **TypeScript 6** requires `rootDir` when `outDir` is set in some layouts (TS5011) and rejects `baseUrl`-only path setups (TS5101); generated configs use `paths` without `baseUrl`.
