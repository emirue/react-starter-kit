# Audit of generated apps (before the architecture refactor)

Scope: the React app create-produx-app generated at commit `a223418` (source: `templates/`). Evidence comes from three generated copies made with that build:

- Enterprise (Base UI, React Router, Axios, MSW, Orval, Playwright): 80 TS/TSX files, 9 test files
- Enterprise with Radix, TanStack Router and Fetch: 83 files
- Standard: 47 files, 6 test files

The target that resolves these findings is [../architecture/frontend-architecture.md](../architecture/frontend-architecture.md). How the code moved is in [migration.md](migration.md).

## Structure

Before:

```text
src/main.tsx  App.tsx  index.css
src/app/{providers,router}.tsx
src/pages/*-page.tsx  src/pages/examples/*.tsx
src/layouts/  src/stores/  src/hooks/  src/config/
src/features/{todos,sign-up,counter,users}/{api,components,schemas,stores,types}/
src/components/{ui/*, theme/*, error-boundary, error-fallback, page-loader}
src/lib/{api-client, api-error, query-client, orval-mutator, utils}
src/api/generated/** (Orval)
```

## Findings

| #   | Finding                                                                                              | Evidence (generated Enterprise copy)                                                                                                                                                                                                            | Resolution                                                                                                                                                                                                                             |
| --- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Pages reach into feature internals; no slice has a public API                                        | 5 deep imports, e.g. `pages/examples/todos-page.tsx` → `@/features/todos/components/todo-list`, `@/features/todos/types/todo`                                                                                                                   | Every slice has an `index.ts`; `eslint-plugin-boundaries` rejects imports that bypass it                                                                                                                                               |
| 2   | No architecture rule is enforced                                                                     | `eslint.config.js` had no import or boundary rules; AGENTS.md stated "Features must not import from each other's internals"                                                                                                                     | `boundaries/dependencies` and `boundaries/no-unknown-files` in the generated `lint`, with `eslint-import-resolver-typescript` so `@/` imports are checked                                                                              |
| 3   | `components/` and `lib/` mixed unrelated roles                                                       | `components/` held shadcn/ui, the theme provider, a user action (mode toggle) and error UI; `components/ui/sonner.tsx` imported `components/theme`                                                                                              | `shared/ui` (design system), `shared/lib/theme`, `features/switch-theme`, `shared/api`                                                                                                                                                 |
| 4   | The Todo type was defined three times; the Orval client was unused                                   | `features/todos/types/todo.ts`, `mocks/handlers.ts`, `api/generated/model/todo.ts`; `api/generated/api.ts` was imported only by a test, and its query keys never matched the hand-written ones                                                  | With Orval the page's `model/todo.ts` re-exports the generated type and `api/todo-api.ts` calls the generated functions; MSW handlers import the type from the page slice                                                              |
| 5   | The same feature lived in different layers per router                                                | TanStack Router kept search validation and the component in `routes/examples/todos.tsx`; React Router kept them in `pages/examples/todos-page.tsx`                                                                                              | Route files are thin in both routers; the page slice exports the component and `validateTodosSearch`                                                                                                                                   |
| 6   | A page render error replaced the whole admin shell                                                   | Probed in both routers: the error boundary sat above the layout                                                                                                                                                                                 | React Router: a pathless child route with `ErrorBoundary` inside the layout. TanStack Router: `defaultErrorComponent`                                                                                                                  |
| 7   | Accessibility violations (axe-core 4.14.1, WCAG 2.0–2.2 A/AA + best practice, 7 routes × light/dark) | nested and duplicate `main` (layout `<main>` inside shadcn `SidebarInset`, which renders `<main>`); `aria-label` on a role-less `div` in the todo list; avatar fallback contrast 4.34:1; sidebar outside landmarks; skip link after the sidebar | One `main` (`SidebarInset id="main"`), sidebar inside `<nav aria-label="Main">`, skip link first, contrast-safe avatar, filter buttons in a labelled `role="group"`. Re-run after the refactor: 0 violations in both variants          |
| 8   | Inconsistent loading, error and empty states                                                         | Each view hand-rolled its own; the users table showed `No users match “”` when there were no users and no search                                                                                                                                | `LoadingState` (`role="status"`), `ErrorState` (`role="alert"`, retry), `EmptyState` in `shared/ui/state.tsx`, used by every data view                                                                                                 |
| 9   | Toggling one todo disabled every checkbox                                                            | `disabled={toggleTodo.isPending}`                                                                                                                                                                                                               | Only the todo being saved is disabled                                                                                                                                                                                                  |
| 10  | Demo error state was module-level mutable state                                                      | `todo-api.ts` kept `serverDown` in a module variable and in component state                                                                                                                                                                     | `simulateError` is part of the query key and sent as a request option                                                                                                                                                                  |
| 11  | Sidebar state had two writers; the settings page read the app store directly                         | shadcn cookie plus Zustand `persist`; `settings-page.tsx` imported `stores/ui-store`                                                                                                                                                            | The settings page uses `useSidebar()` from the provider; the store moved to `app/model` and remains the only persistence that is read. The vendored shadcn sidebar still writes its cookie, which a SPA never reads (left as vendored) |
| 12  | Theme storage key unprefixed and duplicated                                                          | `"theme"` in `theme-context.ts` and in the inline script in `index.html`                                                                                                                                                                        | `<appName>:theme` in both places, like the other stores                                                                                                                                                                                |
| 13  | Examples without a router were rendered inline on the home page                                      | `home-page.tsx` imported feature components when `--router none`                                                                                                                                                                                | Examples need a router; `--router none` generates none                                                                                                                                                                                 |
| 14  | `destructive` text on its tinted background failed contrast (found by the new Storybook a11y tests)  | `--destructive` light value gave 4.0:1 on `bg-destructive/10`                                                                                                                                                                                   | Token darkened to `oklch(0.505 0.213 27.518)`: 5.3:1                                                                                                                                                                                   |

## Measured, not changed

- Import graph: 0 cycles, 0 unresolved imports, 0 feature→feature imports before the refactor.
- Bundle (Enterprise, `vite build`): main chunk 503 kB minified / 158 kB gzip, mostly framework code (react-dom 36%, react-router 22%, Base UI 17%). Routes were already split. No change made; React Compiler is not configured (it needs extra Babel packages on plugin-react 6).
- State: Context only for the theme; Zustand read with single-value selectors; the todo filter in the URL. Kept.
